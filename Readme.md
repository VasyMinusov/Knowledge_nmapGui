# Nmap Panel — документация

Версия: 1.0
Дата: 2026-08-09
Автор: Nmap Panel Team

1. Введение

Nmap Panel – это полнофункциональное веб-приложение для управления сканированием сети с помощью Nmap. Оно предоставляет удобный графический интерфейс (GUI) для запуска сканирования, просмотра результатов, работы с историей, пресетами, расписаниями, базой знаний и генерации отчётов.

Приложение построено на FastAPI (бэкенд) и React + TypeScript (фронтенд). Вся логика взаимодействия с Nmap вынесена в отдельный модуль, результаты парсятся из XML и сохраняются в SQLite.

Ключевые возможности:

    Запуск сканирования с выбором профиля (intense, quick, ping, custom) и дополнительных опций.

    Отображение результатов в виде интерактивной сетки хостов с группировкой по подсетям.

    Детальный просмотр информации о каждом хосте (порты, ОС, время работы, скрипты).

    История всех запущенных сканов с возможностью удаления, просмотра и копирования настроек в пресет.

    Управление пресетами (сохранение, редактирование, удаление, применение).

    Планировщик сканов на основе cron-выражений (с использованием APScheduler).

    Встроенная база знаний по опциям Nmap с поиском и фильтрацией по категориям.

    Быстрая проверка открытости портов (TCP-сканнер) без запуска полноценного Nmap.

    Генерация отчётов в форматах HTML, DOCX, PDF.

    Отмена активного сканирования.

2. Установка и запуск
2.1. Требования

    Python 3.10 или выше

    Node.js 18.x или выше

    Nmap (должен быть установлен в системе и доступен в PATH)

    Git (опционально)

2.2. Установка бэкенда

    Клонируйте репозиторий (или распакуйте архив).

    Перейдите в директорию backend:
    bash

    cd backend

    Создайте виртуальное окружение (рекомендуется):
    bash

    python -m venv venv
    source venv/bin/activate  # Linux/macOS
    # или
    venv\Scripts\activate     # Windows

    Установите зависимости:
    bash

    pip install -r requirements.txt

        Примечание: Для генерации PDF требуется пакет reportlab, а для DOCX – python-docx. Они уже включены в requirements.txt. Если у вас возникнут проблемы с установкой, убедитесь, что у вас есть компилятор C (для reportlab может понадобиться).

    Убедитесь, что Nmap установлен и доступен:
    bash

    nmap --version

    Если Nmap не установлен, установите его через пакетный менеджер вашей ОС (например, sudo apt install nmap для Ubuntu).

    Запустите сервер:
    bash

    uvicorn app.main:app --host 0.0.0.0 --port 5000 --reload

    Бэкенд будет доступен по адресу: http://localhost:5000.

        Swagger-документация API автоматически доступна по адресу: http://localhost:5000/docs.

2.3. Установка фронтенда

    Перейдите в директорию nmap-panel:
    bash

    cd ../nmap-panel   # если вы находитесь в backend

    Установите зависимости Node.js:
    bash

    npm install

    Запустите сервер разработки:
    bash

    npm run dev

    Фронтенд будет доступен по адресу: http://localhost:5173.

2.4. Проверка работы

Откройте браузер и перейдите на <http://localhost:5173>. Вы должны увидеть главный экран приложения с заголовком "NMAP PANEL". Бэкенд должен быть запущен, чтобы все функции работали корректно.
2.5. Настройка переменных окружения (опционально)

По умолчанию бэкенд ожидает запросы с <http://localhost:5173> (CORS уже настроен). Если вы меняете порт фронтенда, обновите allow_origins в backend/app/main.py.

Для бэкенда можно задать путь к базе данных через переменную окружения DB_PATH (в коде используется nmap_panel.db в текущей директории). Скрипты создают папку scans для хранения XML-файлов результатов.
3. Архитектура
3.1. Бэкенд

Структура директорий:
text

backend/
├── app/
│   ├── __init__.py
│   ├── database.py          # Работа с SQLite (CRUD для сканов, пресетов, расписаний)
│   ├── knowledge_base.py    # Статическая база знаний с опциями Nmap, API-роуты
│   ├── main.py              # Создание приложения FastAPI, подключение роутеров
│   ├── models.py            # Pydantic-модели для валидации запросов/ответов
│   ├── nmap_wrapper.py      # Обёртка Nmap: запуск, парсинг XML, отмена, управление статусами
│   ├── report_generator.py  # Генерация отчётов (HTML, DOCX, PDF)
│   ├── scheduler.py         # Настройка APScheduler, управление заданиями
│   └── routes/
│       ├── scan.py          # Эндпоинты для сканирования, истории, пресетов, отчётов
│       ├── schedule.py      # Эндпоинты для расписаний
│       └── port_check.py    # Эндпоинты для быстрой проверки портов
├── scans/                   # Папка для сохранения XML-файлов результатов сканов
├── nmap_panel.db            # SQLite-база данных (создаётся автоматически)
└── requirements.txt

Основные модули:

    database.py: Содержит функции для работы с таблицами scans, presets, schedules. Использует sqlite3.

    nmap_wrapper.py: Отвечает за запуск Nmap в подпроцессе, парсинг XML через xmltodict, ведение словаря статусов в памяти.

    scheduler.py: Инициализирует фоновый планировщик BackgroundScheduler, перезагружает задания из БД при запуске.

    routes/: Группируют эндпоинты по функциональности.

База данных (SQLite):

    scans: хранит информацию о каждом запуске: scan_id (UUID), цели, профиль, опции (JSON), статус, время начала/окончания, путь к XML-файлу, краткую сводку.

    presets: содержит название, цели, профиль, опции (JSON), описание, дату создания.

    schedules: имя, цели, профиль, опции (JSON), cron-выражение, активен/неактивен, дата создания, время последнего запуска, scan_id последнего сканирования.

Взаимодействие: Фронтенд общается с бэкендом через REST API. Для долгих операций (сканирование) используется асинхронный опрос статуса.
4. API Endpoints

Все эндпоинты имеют префиксы:

    /api/scan – сканирование, история, пресеты, отчёты

    /api/schedule – расписания

    /api/knowledge – база знаний

    /api/port-check – проверка портов

4.1. Сканирование
Метод	URL	Описание
POST	/api/scan/start	Запуск сканирования. Тело запроса: { targets: string, profile: string, options?: { os_detection, version_detection, traceroute, scripts } }. Возвращает { scan_id }.
GET	/api/scan/{scan_id}/status	Получение текущего статуса сканирования. Возвращает объект ScanStatus с хостами, прогрессом и сводкой.
POST	/api/scan/{scan_id}/cancel	Отмена активного сканирования.
GET	/api/scan/history	Список истории сканов (с пагинацией через limit и offset).
GET	/api/scan/history/{scan_id}	Получение данных конкретного скана.
GET	/api/scan/history/{scan_id}/hosts	Получение списка хостов для скана (парсинг XML).
DELETE	/api/scan/history/{scan_id}	Удаление записи истории.
GET	/api/scan/{scan_id}/report?format=html|docx|pdf	Генерация и скачивание отчёта.
4.2. Пресеты
Метод	URL	Описание
GET	/api/scan/presets	Список всех пресетов.
GET	/api/scan/presets/{preset_id}	Получение конкретного пресета.
POST	/api/scan/presets	Создание пресета (параметры передаются в query или теле).
PUT	/api/scan/presets/{preset_id}	Обновление пресета.
DELETE	/api/scan/presets/{preset_id}	Удаление пресета.
4.3. Расписания
Метод	URL	Описание
GET	/api/schedule/	Список всех расписаний.
GET	/api/schedule/{schedule_id}	Получение расписания.
POST	/api/schedule/	Создание расписания (тело: { name, targets, profile, options, cron_expression, active }).
PUT	/api/schedule/{schedule_id}	Обновление расписания.
DELETE	/api/schedule/{schedule_id}	Удаление расписания.
POST	/api/schedule/{schedule_id}/run	Принудительный запуск расписания прямо сейчас (не по расписанию).
4.4. База знаний
Метод	URL	Описание
GET	/api/knowledge/options	Получить все опции Nmap (список объектов).
GET	/api/knowledge/categories	Получить список уникальных категорий.
4.5. Проверка портов
Метод	URL	Описание
POST	/api/port-check/check	Проверить порты. Тело: { host: string, ports: number[], timeout?: number }. Возвращает статус каждого порта.
5. Инструкция по использованию
5.1. Запуск нового сканирования

    Откройте приложение в браузере (по умолчанию http://localhost:5173).

    На главном экране (вкладка Scan) вы увидите форму NEW SCAN.

    Выберите пресет (опционально) из выпадающего списка, чтобы автоматически заполнить поля.

    Введите цели (targets). Можно указывать:

        IP-адрес (например, 192.168.1.1)

        CIDR-диапазон (например, 192.168.1.0/24)

        Диапазон через дефис (например, 192.168.1.1-254)

        Доменное имя (например, example.com)

        Несколько целей через запятую (например, 192.168.1.1, example.com)

    Выберите профиль:

        Intense (-T4 -A -v) – агрессивное сканирование с определением ОС, версий и трассировкой.

        Quick (-T4 -F) – быстрое сканирование только 100 наиболее распространённых портов.

        Ping Sweep (-sn) – только обнаружение хостов без сканирования портов.

        Custom – позволяет вручную указать скрипты (поле Scripts).

    При необходимости включите дополнительные опции: OS Detection, Version Detection, Traceroute.

    Нажмите ▶ START SCAN. Сканирование запустится в фоновом режиме.

    Справа отобразится статус выполнения и прогресс. После завершения вы увидите список хостов.

    Если вы хотите остановить сканирование, нажмите кнопку CANCEL SCAN (появляется во время выполнения).

5.2. Просмотр результатов сканирования

После завершения сканирования в правой панели SCAN RESULTS отображаются:

    Прогресс-бар и сводка (количество найденных хостов).

    Сетка хостов с группировкой по подсетям. Каждый хост представлен плиткой:

        Зелёная рамка – хост доступен (up).

        Серая рамка – хост не отвечает (down).

        Число в углу – количество открытых портов.

    Клик по плитке открывает модальное окно с деталями:

        IP-адрес, hostname (если есть)

        Статус (up/down)

        Определённая ОС (если использовалась опция -O или -A)

        Uptime (если доступен)

        Таблица открытых портов с указанием порта, протокола, названия сервиса и версии.

    Над сеткой есть поле Search (поиск по IP или hostname) и фильтр по статусу хоста (All, Up, Down).

    Кнопки HTML, DOCX, PDF позволяют скачать отчёт в соответствующем формате (подробнее в разделе 5.8).

5.3. История сканов

Перейдите на вкладку History. Здесь представлена таблица всех ранее запущенных сканов.

    В каждой строке: дата, цели, профиль, статус, краткая сводка.

    Кнопки действий:

        View – открывает модальное окно с результатами выбранного скана (аналогично просмотру результатов).

        Copy preset – создаёт пресет на основе параметров этого скана (открывается форма редактирования пресета с предзаполненными полями).

        Download – скачивает отчёт в формате по умолчанию (можно выбрать формат в диалоге).

        Delete – удаляет запись истории (вместе с XML-файлом).

5.4. Управление пресетами

Вкладка Presets позволяет сохранять часто используемые конфигурации сканирования.

    + Create Preset – открывает форму создания.

        Name – уникальное имя пресета.

        Targets (опционально) – можно оставить пустым, чтобы вводить при старте.

        Profile – как при сканировании.

        OS Detection, Version Detection, Traceroute – чекбоксы.

        Scripts – поле для указания скриптов (только для профиля Custom).

        Description – произвольное описание.

    Select – применяет пресет, переключая вас на вкладку Scan и заполняя форму.

    Edit – изменяет существующий пресет.

    Delete – удаляет пресет.

5.5. Планировщик (расписания)

Вкладка Schedules позволяет настроить автоматические сканирования по расписанию.

    + ADD SCHEDULE – открывает форму создания расписания.

        Name – название расписания.

        Targets – цели (обязательно).

        Profile и опции – аналогично сканированию.

        Cron Expression – выражение cron (например, 0 3 * * * для ежедневного запуска в 3:00). Формат: минуты часы день_месяца месяц день_недели.

        Active – флаг, включающий/отключающий расписание.

    View – отображает информацию о расписании (в текущей версии просто показывает уведомление).

    Edit – изменяет расписание.

    Run – запускает сканирование немедленно, независимо от расписания (полезно для тестирования).

    Delete – удаляет расписание.

Расписания хранятся в БД и автоматически загружаются в APScheduler при старте бэкенда.
5.6. База знаний

Вкладка Knowledge содержит справочную информацию по опциям Nmap.

    Карточки с опциями: флаг, категория, описание, пример использования.

    Вверху: поле поиска (по флагу, названию, описанию или примеру) и выпадающий фильтр по категории.

    Это статический список, но его можно легко расширить, добавив новые записи в массив OPTIONS_DATA в файле backend/app/knowledge_base.py.

5.7. Быстрая проверка портов

Вкладка Port Check позволяет проверить открытость портов без запуска полноценного Nmap.

    Host – IP-адрес или домен.

    Ports – поле для ввода портов. Можно указать:

        Одиночные порты через запятую (например, 80,443,22)

        Диапазоны через дефис (например, 20-25)

        Комбинировать (например, 80,443,20-25,3306)

    Кнопка Add добавляет введённые порты в список; Clear all очищает список.

    Быстрые кнопки (SSH, HTTP, HTTPS и т.д.) добавляют соответствующие порты.

    Нажмите ▶ CHECK PORTS – выполняется асинхронное TCP-подключение к каждому порту с таймаутом (по умолчанию 2 секунды).

    Результаты отображаются в таблице: порт, статус (open/closed/error), сообщение об ошибке (если есть).

    Сводка показывает количество открытых/закрытых/ошибочных портов.

5.8. Генерация отчётов

Отчёты можно скачать двумя способами:

    Из результатов сканирования (вкладка Scan) – после завершения скана в правой панели есть кнопки HTML, DOCX, PDF. При нажатии выбранный формат скачивается автоматически.

    Из истории (вкладка History) – в каждой строке есть кнопка Download. При нажатии появится диалог с выбором формата (html, docx или pdf). После выбора файл будет скачан.

Отчёты генерируются на основе XML-файла результата, сохранённого при сканировании. Они содержат:

    Общую информацию о скане (ID, цели, профиль, время начала и окончания, статус, сводку).

    Список хостов, для каждого – IP, hostname, статус, ОС (если определена), uptime.

    Для каждого хоста – таблица открытых портов с портом, протоколом, сервисом и версией.

Поддерживаемые форматы:

    HTML – стилизованная веб-страница с monospace-шрифтом и неоновой цветовой гаммой.

    DOCX – документ Microsoft Word с таблицами.

    PDF – PDF-документ с использованием библиотеки ReportLab (страницы A4).

6. Настройка и конфигурация
6.1. Изменение портов

    Бэкенд: В команде запуска uvicorn app.main:app --host 0.0.0.0 --port 5000 измените значение порта. Также не забудьте обновить CORS-настройки в app/main.py: в allow_origins добавьте новый адрес фронтенда.

    Фронтенд: В файле vite.config.ts можно изменить server.port (по умолчанию 5173). В src/api/nmapApi.ts измените базовые URL константы (SCAN_BASE, SCHEDULE_BASE и т.д.) при необходимости.

6.2. Путь к Nmap

По умолчанию подразумевается, что команда nmap доступна в PATH. Если она находится в другом месте, измените вызов в nmap_wrapper.py (функция build_nmap_args возвращает список, где первый элемент – "nmap"). Можно указать полный путь, например, ["/usr/local/bin/nmap", ...].
6.3. База данных

По умолчанию используется SQLite-файл nmap_panel.db в директории backend. Чтобы изменить путь, отредактируйте переменную DB_PATH в app/database.py.
6.4. Директория для сохранения XML

Результаты сканирования сохраняются в папку scans внутри backend. Если вы хотите изменить это, отредактируйте SCAN_DIR в nmap_wrapper.py.
6.5. Таймауты и другие параметры

    В routes/port_check.py таймаут по умолчанию – 2 секунды. Его можно переопределить в теле запроса.

    В nmap_wrapper.py частота обновления статуса не регулируется (она управляется фронтендом, который опрашивает каждые 2 секунды). При необходимости можно изменить интервал в useScan.ts.

7. Возможные проблемы и их решение
7.1. Nmap не запускается

Симптом: При старте сканирования ничего не происходит, в логах ошибка FileNotFoundError или [Errno 2] No such file or directory: 'nmap'.
Решение: Убедитесь, что Nmap установлен и доступен из командной строки. Проверьте командой nmap --version. Если Nmap установлен в нестандартном месте, укажите полный путь в nmap_wrapper.py.
7.2. Ошибка парсинга XML

Симптом: Сканирование завершается, но результаты не отображаются, в логах ошибка парсинга.
Причина: Nmap может выдавать невалидный XML при определённых условиях (например, если сканирование было прервано).
Решение: Убедитесь, что сканирование завершается корректно. Если ошибка повторяется, проверьте, установлена ли библиотека xmltodict (она есть в requirements.txt).
7.3. Не генерируются отчёты DOCX/PDF

Симптом: При попытке скачать DOCX или PDF возникает ошибка.
Причина: Не установлены зависимости python-docx и/или reportlab.
Решение: Установите их вручную:
bash

pip install python-docx reportlab

7.4. Планировщик не запускает задания

Симптом: Расписания созданы, активны, но сканирование не запускается в указанное время.
Причина: APScheduler может не работать в некоторых окружениях (например, при использовании --reload в разработке). Также проверьте, что время в системе соответствует вашему часовому поясу.
Решение: Перезапустите бэкенд. Если проблема сохраняется, проверьте логи на наличие ошибок при добавлении заданий.
7.5. Проблемы с CORS

Симптом: Запросы с фронтенда блокируются, в консоли браузера ошибка CORS.
Решение: Убедитесь, что в app/main.py в allow_origins указан правильный адрес фронтенда. Для разработки можно разрешить все источники: ["*"] (не рекомендуется для продакшена).
7.6. Низкая производительность при большом количестве хостов

Симптом: Интерфейс подтормаживает при отображении сотен хостов.
Решение: В компонентах используется виртуализация только на уровне сетки (без react-window). При необходимости можно добавить пагинацию или виртуализацию.
